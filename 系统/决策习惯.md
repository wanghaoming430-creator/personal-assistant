# 决策习惯

> 本文件保存当前有效的**全局**助手工作规则 R 和没有对错之分的分歧 F。纠错事件 C 的历史记录在 `系统/助手纠错档案.md`，日常同类任务只查本文件的 R 规则，需要追溯时再打开档案。项目专属规则留在该项目 `项目记忆.md` 或 `项目技能/`，不进入本表。它不描述用户性格，也不代替个人画像或长期记忆。

## 准入规则

- **什么算纠错：** 用户明确指出助手说错、做错、记错或违反已确认边界。建立 C 事件，写入 `系统/助手纠错档案.md`。
- **什么算分歧：** 双方看法不同但没有事实或规则上的对错。进入 F 分歧记录，不计为错误。
- **什么不记：** 用户补充新信息、改变主意或单纯追问，不算助手错误。
- **助手在输出前自行发现并修正的错误：** 按系统更新日志记录；已经输出给用户的，必须明确回显修正内容。
- **怎么使用：** 回答同类问题前检索 R 规则，先检查适用边界；不符合边界时不得套用。
- **记录回显：** 新增 C 或 F 记录后，用一句话向用户回显本次记录的类别和核心修正；不把普通补充信息误记为纠错。
- **C 编号：** 在 `系统/助手纠错档案.md` 中从 C-01 起，全库唯一，只增不减、不复用、不重排。
- **R 编号：** R-01 起，全库唯一，只增不减、不复用、不重排。规则内容可更新，编号不变。
- **状态：** 未复发 / 已复发 / 被推翻。被推翻时追加替代规则编号，原记录不删除。
- **层别：** 判断层、约束层、执行层、表达层、调用层。调用层子类为召回漏、召回噪、路由错。
- **硬门槛：** 写不出适用边界的内容，不得进入 R 规则表，只能保留为 C 事件。

### 单条 R 的建议字段

新增或修订 R 时，至少写清：

- R 编号、规则名称
- 适用范围：全局通用 / 项目类型通用（仅作候选方法引用）/ 项目专属（不进入全局 R）
- 适用场景、触发信号
- 必须执行、禁止执行
- 不适用边界
- 来源：C 编号、用户明确指令或验证记录
- 正向验证、反向证据
- 状态：候选 / 待验证 / 生效 / 待复核 / 已失效 / 已替代
- 替代规则和原因

> 现有 R 表已用「场景」「怎么判」「边界」「依据」表达对应信息，不强制重排；新增规则按上述字段写全。

### 规则升级与生效

- 同一根因再次出现时，先检索旧规则，不重复制造近义规则。
- 同一根因第 3 次出现时，合并到最早的根因记录，保留原编号并注明关联事件编号。
- 规则被更高层级规则替代时，旧规则标记「被推翻」，追加替代规则编号，不删除历史。
- 需要写入 `系统/运行入口.md` 或其他系统规则源时，遵守系统文件的单独修改授权要求；不得因为记录了纠错就自行修改系统规则文件。
- 新规则必须能指出来源、适用边界和可检查的行为。没有边界或没有证据的内容只作为候选，不宣布为正式规则。
- 由单个项目问题形成的规则先进入该项目技能或项目记忆，不自动进入本表；跨项目提级须提供多个独立证据、共同根因和共同边界，见 [[系统维护/规则适用范围与升级规范]]。
- 用户明确撤销或修改规则时，以新指令为准；旧规则保留编号和历史，标记已失效或已替代，并链接新规则。
- 未复发不等于已验证；规则调用次数不等于正确执行次数。

## 三、同类问题巡检

- 每累计 10 条 C 事件，检查错误集中在哪个层级，是否需要新增检查动作。

- 相同事件若同时涉及 `系统/助手纠错档案.md` 的 C 和 `个人/记忆.md` 中的 B，只保留一份完整主记录；另一处只留编号链接，不复制事件详情。
