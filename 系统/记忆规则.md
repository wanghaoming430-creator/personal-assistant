# 记忆触发、生命周期与检索规则

> 本文件是记忆系统唯一的触发和生命周期规则入口。记录分散存放，按事件和主题检索；不要求每次对话读取全部记忆文件。项目专属经验先归项目记忆，个人记忆只保存跨个人、跨场景仍成立的内容。

## 一、先判断是否触发

| 触发事件 | 处理动作 | 主记录位置 |
|---|---|---|
| 用户明确纠正助手已经输出或执行的错误 | 建立 C；检查是否命中现有 R | `系统/助手纠错档案.md` |
| 相似任务可能复发助手旧错误 | 回答前检索匹配的有效 R | `系统/决策习惯.md` |
| 项目内出现事实、决策、经验、偏差或衔接信息 | 先写项目记忆；不自动进个人记忆 | 该项目 `项目记忆.md` |
| 项目内形成可重复的方法 | 建立项目技能候选；验证后再正式化 | 该项目 `项目技能/` |
| 项目/任务结果明显偏离目标且有可复用教训 | 判断归属：项目专属进项目记忆，跨场景个人教训进 B | 项目记忆或 `个人/记忆.md` |
| 用户分享了长期有用的亲身经历 | 记录 E | `个人/记忆.md` |
| 多次出现值得验证的行为/认知变化 | 建立 I，记录支持与反例 | `个人/记忆.md` |
| 双方看法不同但没有证据判定对错 | 记录 F | `个人/记忆.md` |
| 用户比较有现实代价的选项、作重要选择或跟进既有决定 | 查决策索引，建立/更新 D | `内容/决策/` |
| 用户明确提供稳定事实、偏好、目标或约束 | 提出 P/M 候选；确认后更新 | `个人/个人画像.md` / `个人/长期记忆.md` |
| 记忆到达复核日期、遇到冲突或发现可能失效 | 核验、更新有效性，不直接删除 | 对应原记录 |
| 用户要求执行每周睡眠学习 | 按本周真实问题增量检查规则、项目记忆和技能 | `系统维护/睡眠学习规范.md` |
| 普通闲聊、一次性信息、临时情绪、未验证猜测 | 不触发长期写入 | 不记录 |

## 二、记忆分类与唯一归属

| 代码 | 含义 | 正本位置 |
|---|---|---|
| E | 个人经历与经验 | `个人/记忆.md` |
| I | 阶段性觉察/待验证模式 | `个人/记忆.md` |
| B | 任务或项目偏差（项目专属先写项目记忆） | `个人/记忆.md` |
| F | 无对错的分歧 | `个人/记忆.md` |
| C | 助手已经发生的错误 | `系统/助手纠错档案.md` |
| R | 当前有效的助手工作规则 | `系统/决策习惯.md` |
| D | 一项具体重要决策及其复盘 | `内容/决策/` |
| P | 经用户确认的个人稳定信息 | `个人/个人画像.md` |
| M | 经用户确认的跨场景长期记忆 | `个人/长期记忆.md` |

同一事件只设一个完整主记录。其他文件只写编号或链接，不复制正文。C 不得转写成 P/M；D 不自动生成 M；F 不得记为 C。

**个人记忆边界：** E/I/B/F 只保存属于用户个人经历、跨场景行为模式或无项目归属的任务偏差。由单个项目的目标、资料、平台或流程产生的经验、偏差和失败原因，主记录放该项目 `项目记忆.md`；只有同时具备跨个人、跨场景价值，且经用户确认时，才进入个人记忆候选。项目记忆不得自动转成个人画像或长期记忆。

## 三、触发后的标准顺序

1. **识别：** 判断是否满足触发门槛，不因“也许以后有用”就记录。
2. **查重：** 按主题、根因、人物/项目或编号检索现有条目。
3. **核源：** 标明用户原话、文件、实际结果或外部来源；事实与解释分开。
4. **分流：** 按唯一归属追加到主记录。
5. **设有效性：** 判断是否需要复核日期、失效条件或替代关系。
6. **审批：** P/M 和受保护规则必须经用户确认；候选不等于生效。
7. **摘要同步：** 只有已确认且跨任务高频的信息，才同步到 `个人/用户上下文摘要.md`。
8. **回显：** 重要记录用一句话说明类型和去向；不汇报每次内部检索。

## 四、记忆生命周期

所有长期有效记录都要能够回答：它来自哪里、何时确认、当前是否仍适用、什么时候需要重新核对。

### 1. 有效性字段

对 E/I/B/F、C/R、P/M 和 D 按适用程度使用以下字段；不是每个字段都必须填：

- `有效性`：待确认 / 待验证 / 有效 / 待复核 / 已失效 / 已替代。
- `来源`：用户原话、文件路径、结果证据或可靠来源。
- `确认日期`：信息被用户确认或事实被核实的日期。
- `最后核验日期`：最近一次确认其仍适用的日期。
- `复核日期`：预计需要重新核对的日期；稳定且不易变化时可省略。
- `失效条件`：哪些变化会让这条信息不再适用。
- `替代编号`：被新条目取代时，指向新编号。

### 2. 生命周期状态

| 有效性 | 含义 | 使用规则 |
|---|---|---|
| 待确认 | 来源或用户确认不足 | 不作为确定的用户事实使用 |
| 待验证 | 有合理线索，但证据尚不足 | 可作为假设，不可当成稳定规则 |
| 有效 | 当前证据支持且仍适用 | 可在相关任务中按需召回 |
| 待复核 | 到达复核日期或出现变化信号 | 暂时降低权重；影响结论时先核验 |
| 已失效 | 事实、环境或条件已不再成立 | 保留历史，不再作为当前规则 |
| 已替代 | 已由新记录接替 | 保留旧记录并链接替代项 |

### 3. 复核与失效处理

- 复核日期到期不等于自动失效；应标记“待复核”，在下一次相关任务中核验。
- 不相关的过期记忆不必主动打扰用户；只有它会影响当前建议时才询问。
- 稳定事实不必机械设置短期复核日期；易变信息（目标、工作状态、地点、预算、项目状态、偏好等）应设置复核条件或日期。
- 发现信息失效时，不删除、不覆盖原文；追加变更说明，标记“已失效”或“已替代”。
- 旧信息和新信息冲突时，先检查时间、适用场景和表达是否明确。用户明确表示“已经改变”时以新信息为准并保留旧记录；若只是当前情境不同，记录为情境例外；仍不清楚时只问一个关键问题。
- 不因模型长时间没看到反例，就自行断言一条记忆仍然有效。

### 4. 摘要同步

`个人/用户上下文摘要.md` 只包含用户已确认、跨任务高频、当前仍有效的短事实。摘要必须链接到原记录，并定期清理失效或低频内容。摘要不是独立证据源，发生冲突时回到原记录核验。

## 五、各类触发门槛

### C：助手纠错

- 只有助手已输出给用户或已执行错误操作，才建立 C。
- 用户补充新事实、改变偏好或表达不同意见，不自动算 C。
- C 写明错误、正确内容、根因、适用场景、来源、关联 R 和复核状态。
- 新 C 建立后检查是否已有 R；如果有，评估是否复发或需要修订。

### R：助手工作规则

- 规则必须可执行、可检查，并写清适用场景、触发信号和不适用边界。
- 用户明确要求“以后都按此执行”的具体规则，可直接按用户指令设为有效；由单次错误推导的普遍规则先标记待验证。
- 相同根因再次出现时修订旧 R，不重复建立近义规则。
- 规则被推翻或不再适用时保留旧编号，标记已替代/已失效并链接新规则。
- R 只约束助手行为，不推断用户人格。
- 全局 R 只保存全局有效的助手工作规则；由单个项目问题形成的规则先进入该项目技能或项目记忆，不自动进入全局 R。
- 从多个项目独立出现的相似问题中提炼通用规则时，必须证明共同根因和共同适用边界；无法证明则保留在各项目。

### C/R 召回衰减

C 保存已经发生的错误。**历史事件不删除、不因时间到期自动失效；衰减的是日常召回优先级。**

| 召回级别 | 条件 | 使用方式 |
|---|---|---|
| 高优先级 | 严重错误、相关任务中复发、可能造成明显损失或规则尚未验证稳定 | 在匹配任务中优先提醒并读取必要历史 |
| 场景召回 | 已纠正，仍有相关场景复用价值 | 仅在相似任务或追溯时读取 |
| 历史追溯 | 已有充分纠正证据，长期未见相关复发，且对当前任务影响低 | 默认不加载，需要审计、复核或追溯时读取 |

- 衰减不得只按“多少天未复发”判断。至少检查严重程度、场景匹配度、是否真正执行过规则、成功验证证据、是否出现反例。
- 严重错误不会仅因长期未复发自动降为低优先级。
- R 只保存当前有效规则，不保存错误流水。未复发不等于已验证；规则调用次数不等于正确执行次数。
- 项目环境、模型能力、流程或用户要求发生变化时，触发规则复核。

### 相似记录合并

| 新记录与旧记录关系 | 正确处理 |
|---|---|
| 同一错误事件的补充 | 追加到原 C，不新建事件 |
| 不同时间发生、相同根因的错误 | 分别建立 C，关联同一 R |
| 相同规则的补充说明 | 修订原 R，保留变更记录 |
| 相似措辞、不同根因 | 不合并 |
| 同一根因、不同适用范围 | 分别记录边界，必要时建立共享方法候选 |
| 规则互相冲突 | 保留双方证据，形成冲突提案，不自动覆盖 |
| 项目规则与全局规则相似 | 先核对是否具有全局适用性，不自动上推 |

相似检索只负责找候选；最终合并根据事件身份、根因、场景、触发信号、执行动作和边界判断，不按语义相似度自动合并。

### 项目记忆路由

- 项目事实、用户对该项目的要求、决策链接、已验证经验、项目纠错、当前进展和待恢复上下文，写入该项目 `项目记忆.md`。
- 项目记忆不复制完整决策正文，不重复全局规则，不自动转成个人画像或长期记忆。
- 项目技能只在出现真实、可重复的工作场景后创建；一次性工作不沉淀为技能。
- 项目状态只使用进行中、等待外部、已结项、归档；等待外部不等于结项，归档项目默认不参与日常运行。

### E/I/B/F：个人经验

- E 记录亲历事实、当时判断、实际结果和可复用教训。
- I 记录重复出现的现象、观察周期、支持证据和反例；单次事件只能作为观察线索。
- B 记录目标/预期、实际、差异、根因和下次修正动作；助手已输出的错误归 C，不重复归 B。
- F 记录没有证据判定对错的分歧；后续新证据追加在原条目。
- 经验和觉察不自动进入画像或长期记忆。
- 项目专属的 B 和教训先写项目记忆；只有脱离该项目仍成立的个人教训，才进入 `个人/记忆.md`。

### D：重要决策

- 存在真实选项、代价权衡或长期影响时建立 D；日常小选择不建档。
- 进入决策任务先查 `内容/决策/决策索引.md`，再按主题读取相关记录。
- 同一事项的执行、结果、复盘和纠正追加到原 D。
- 决策有新证据、条件变化或原假设失效时，追加修正历史并更新有效性/复核安排。
- 只有复盘后形成跨场景、经用户确认的原则，才进入 M。

## 六、主动信息采集与每日回顾

- 渐进采集规则和主题顺序见 [[用户信息采集计划]]。
- 每次最多提出一个有效问题；用户当前任务优先，用户可以跳过或暂停。
- 每日回顾只在用户进入回顾场景或明确要求时执行；不要求每天形成日记或记忆。
- 回答只作为信息来源；画像和长期记忆写入仍需用户确认。
- 没有外部调度能力时，不得声称能在用户未开启会话时主动提醒。

## 七、读取触发

- 普通任务：不读历史记忆。
- 个性化任务：先读用户摘要；不足时按主题查 P/M。
- 项目任务：先读项目定位和项目记忆；只有需要具体做法时才读对应项目技能。
- 跨项目问题：先判断可共享的方法，再核对适用边界，不批量加载其他项目记忆。
- 与助手历史错误相似：先读匹配 R；追溯原因时再读关联 C。
- 个人经历/行为模式相关：按 E/I/B/F 和主题查 `个人/记忆.md`。
- 重要决策：读决策索引及同主题记录，不读全部决策档案。
- 复核、冲突或失效：只读取相关条目及来源，不全量扫描。
- 周期回顾：限定日期和主题范围，不做全库回顾。

## 八、禁止事项

- 不因每次聊天都发生就每次写记忆。
- 不把助手错误记成用户偏好。
- 不把一次性表达推断为长期事实。
- 不复制同一事件到多个文件。
- 不把过期条目继续当作当前事实。
- 不自动把候选提升为已确认记忆。
- 不为了“提高召回率”把整个 Vault 塞进上下文。
