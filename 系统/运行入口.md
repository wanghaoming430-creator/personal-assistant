# 运行入口

> 云端 Agent 与本地应急 Agent 处理本知识库时的轻量入口。它规定读取顺序、项目识别和上下文边界，不要求每次加载全库。

## 一、运行原则

1. 知识库以标准 Markdown/YAML 为数据主体，Obsidian 负责浏览、编辑和索引。
2. 云端 Agent 是主力工作环境；本地模型只作断网或节省云端 Token 时的应急，不作为运行前提。
3. 模型和插件可替换，文件结构、编号、属性、唯一归属和审批规则不随模型变化。
4. 只读取完成当前任务所需的最少文件。没有触发条件，不主动读取画像、记忆、决策历史或整个目录。
5. 不把模板、工作台代码、索引页、历史日志当作常驻上下文。
6. 当前用户明确指令优先于历史文件；需要改变长期规则时，不静默改写。
7. 项目之间默认隔离：一个项目的定位、记忆、技能和约束不自动套用到其他项目。
8. 规则适用范围默认取最小值；项目专属要求先留在项目层，见 [[系统维护/规则适用范围与升级规范]]。
9. 云端处理意味着必要资料会发送给模型服务商；只提交任务必需片段，敏感信息先脱敏。
10. 回复先回答问题，少套话、少复述、不机械套格式；详见 [[助手回复规范]]。

## 二、云端与本地分工

| 模式 | 运行方式 | 职责 |
|---|---|---|
| 云端主力 | 用户在所选云端 Agent 平台直接操作知识库 | 项目工作、规则治理、跨文件整合、检索分析、睡眠学习 |
| 本地应急 | Obsidian Smart Composer 1.2.9 + Jan + Qwen3-8B Q4 | 断网或主动切换时处理单个短小、低风险微任务 |

- 云端 Agent 不要求接入 Smart Composer，也不依赖 Smart Composer 提供文件访问。
- 两类模型读取同一套知识库文件，不设置资料分级授权；检索按任务相关性和上下文容量控制。
- 本地模型实际最大上下文按 999 tokens 硬上限处理，详细预算与配置见 [[系统维护/Smart Composer本地配置说明]]。
- 本地模型产生的规则、记忆或技能更新只作为候选，不能自行批准。
- 本地模式不执行完整睡眠学习、跨项目规则泛化、C/R 冲突裁定和全库检索分析。

## 三、最小读取顺序

| 层级 | 读取内容 | 触发条件 |
|---|---|---|
| L0 当前任务 | 用户当前消息、当场提供的材料 | 每次 |
| L1 运行规则 | 本文件、`系统/系统规则.md`；复杂表达/交付/纠错时查 `系统/助手回复规范.md` | 每次按任务复杂度 |
| L2 用户摘要 | `个人/用户上下文摘要.md` | 个性化建议、用户约束、长期目标或协作偏好 |
| L3 项目资产 | 项目首页、`项目定位.md`、`项目记忆.md`、当前任务需要的一份或少量项目技能 | 明确的项目任务 |
| L4 专项资料 | 指定知识、流程、画像、长期记忆、记忆或决策条目 | 当前任务确实需要 |
| L5 历史证据 | 原始对话摘录、旧决策、纠错事件、日志 | 需要核验来源、复发、变化或争议时 |

不因某个文件中存在链接就自动展开全部链接。

## 四、项目识别与读取路径

接到任务先判断是否属于某个正式项目：

1. 用户点名项目，或任务文件位于 `内容/项目/项目名/`，按该项目处理。
2. 无法判断时只问一个关键问题，不自行猜项目。
3. 项目首页负责导航和状态；项目定位说明目标、角色、边界和质量标准；项目记忆保存事实、决策链接、经验和衔接信息；项目技能只在真实、可重复的任务中调用。
4. 只读取当前任务需要的项目资产，不把项目定位、项目记忆和全部技能一起加载。
5. 项目状态只使用四种：进行中、等待外部、已结项、归档。等待外部不等于已结项；归档项目默认不参与日常运行和周度学习。
6. 跨项目问题先识别可共享的方法，再核对适用边界，不把某个项目的专属规则当全局规则。

## 五、任务路由

- 普通问答：只用当前问题与必要规则，不读个人资料。
- 项目任务：先识别项目，再读项目首页、项目定位、项目记忆和必要技能；任务安排需要时再读 `个人/本周清单.md`。
- 跨项目任务：读取相关项目的定位或共享方法，核对边界后再复用；不批量套用项目规则。
- 个性化建议：先读 `个人/用户上下文摘要.md`，不足时再按主题查画像/长期记忆。
- 新建/整理知识：读目标目录相关正式文件；创建或重构时才读对应一份模板。
- 重要决策：触发 `内容/决策/决策索引.md`，查同主题记录；不扫描全部决策全文。
- 助手纠错：先查 `系统/决策习惯.md` 的有效 R；只有追溯原因或验证时才查关联 C。
- 个人经验/行为模式：按主题检索 `个人/记忆.md` 对应条目；项目专属经验先查项目记忆。
- 用户信息引导/每日回顾：只有用户进入每日计划、每日引导/回顾模式，或当前会话确有必要时，才读 `系统/用户信息采集计划.md`；每次最多问一个问题，任务优先。
- 检索效果检查：规则变更、检索失败或月度抽样时，按 `系统维护/检索验收规范.md` 执行。
- 每周睡眠学习：用户输入 `/每周睡眠学习` 或明确提出时，按 `系统维护/睡眠学习规范.md` 执行；本地 999-token 模式不执行。
- 本地微任务：按 [[系统维护/提示词库/Smart Composer本地微任务提示词]] 执行单个短任务。
- 周期回顾：只读取指定周期记录，不全库扫描。

## 六、写入与确认

- 普通知识整理可在指定范围内进行，保留来源，不覆盖原始证据。
- 项目事实、决策链接、经验和衔接信息写入该项目 `项目记忆.md`；项目专属纠错和方法写入项目技能，不自动升级为全局规则。
- 记忆、纠错事件和决策复盘按 `系统/记忆规则.md` 的触发、去重和有效性规则追加。
- 个人画像、长期记忆、系统规则、助手人格、回复规范的新增/修改/删除，先给出差异、来源和理由，得到用户明确确认后执行。
- 删除、覆盖、批量重命名及库外操作，每次单独确认。
- 不将本库内容自动写入模型平台的长期记忆或外部服务记忆；本库是唯一正式记录源。

## 七、上下文预算

1. 不加载整个 Vault，不把整个目录作为附件。
2. 优先读摘要、索引命中条目和明确指定文件；先取 1—3 个高相关结果，不足再扩大。
3. 工作台、模板、索引页、附件、历史日志默认不进入模型上下文；索引只负责定位。
4. 引用用户信息时优先使用摘要中的短事实；只有决策依赖细节时才打开原始记录。
5. 不把原始资料整段复制进摘要或记忆卡片；保留链接和来源定位。
6. 每次检索结束不必生成报告；只有失败、冲突或验收抽样才留痕。
7. 本地模式单次请求总上下文控制在约 800 tokens 以内，不把 999 当日常目标。

## 八、冲突处理

用户当场明确指令 > 已确认系统规则 > 项目定位/项目记忆/项目技能 > 已确认画像/长期记忆 > 专项文件历史记录 > 模型推断。

- 项目规则与全局规则冲突时，以全局规则为准；用户明确说“这个项目例外”时，把例外写进项目定位或项目记忆，并标明范围和期限。
- 历史信息与新信息冲突时，不凭一句模糊表达自动覆盖旧记录；先判断是临时例外、真实变化还是语义误解。涉及稳定信息且无法判断时，只问一个关键问题。

## 九、每日引导能力边界

本文件不能在用户未打开对话时主动推送消息。没有配置外部提醒或日程服务时，每日引导只能在用户进入会话或打开每日入口后触发，不得声称已设置后台自动提醒。
