# 模板使用说明

> 本文件是模板库的导航和使用规范。只有用户要求新建文件、重构文件结构或升级模板时才读取；不属于日常知识库运行资料。

## 一、先判断是否真的需要模板

模板用于产出一份独立、需要长期保存或反复使用的正式文件。以下情形通常不需要创建正式文件：

- 普通问答、临时解释、一次性计算或短期建议。
- 尚未确定是否保留的零散想法；先用即时想法或直接留在对话中。
- 只是更新已有文件中的一个事实或进度，不涉及结构调整。
- 为了“完整”而把一段普通对话拆成多份记录。

需要创建时，先明确产出物、保存位置和未来用途，再选一份主模板。

## 三、模板调用规则

1. **只读取一份主模板。** 如果本次任务需要多份正式产出物，才分别调用对应模板；不要为了“了解全貌”载入全部模板。
2. **先看正式文件。** 若目标文件已经存在，先判断是补内容还是重构；只是补充事实时不需要重套模板。
3. **按需读取关联规则。** 如创建决策记录，必要时读取决策规则；如更新画像，读取权限规则和对应提案模板。不要把所有系统规则都加载进来。
4. **模板说明只在制作时参考。** 正式文件完成后，以正式文件为准；日常运行、执行、跟进和回顾不回看模板。
5. **先查重再创建。** 搜索同主题、同项目、同决策编号和同一事件；命中时更新原文或追加历史，不创建近义副本。
6. **模板是结构，不是任务。** 模板中的问题、检查项、示例和日期不自动变成用户的待办或提醒。

## 四、逐类填写规范

- **01—03 系统入口/规则/人格：** 只写当前确实生效的链接、约束和协作原则。不要把历史过程塞进入口，不要复制回复话术。
- **04—05 画像/长期记忆：** 只写有来源、适用范围和确认依据的信息。画像与长期记忆未经用户确认不得落正本；易变条目补充有效性和复核字段。
- **06—09 清单/项目/知识/SOP：** 一份任务只保留一个任务源；项目首页只做导航和状态，项目目标、范围与质量标准放项目定位，项目事实与衔接信息放项目记忆；项目记录里程碑而非平行待办；知识记录结论、依据、限制；SOP 必须可执行并写明停止条件。
- **10—14 文献参考：** 书籍、电影、人物、地点、播客分别记录对象信息和个人体验；外部事实保留来源，易变信息注明核验日期；不虚构阅读、观看、访问或收听经历。
- **15 剪报：** 保留题名、作者、发布日期和原文链接；作者观点与用户理解分开，摘录只保留必要短段，不整篇复制。
- **16—19 日志与回顾：** 即时想法和日记保持低摩擦；阶段/月度/年度回顾只提炼有价值主题，不要求全量整理，不把回顾变成逐条考勤。
- **20 人生决策：** 达到重大决策门槛才创建；记录当时信息与假设，决定后在同一文件追加执行、复盘和修正，不覆盖历史。
- **21—22 更新提案：** 一份提案处理一项或少量相关更新；写清来源、反证、边界和失效条件，用户确认前不写入正本。
- **23—27 版式/命名/权限/流转/模型接入：** 仅用于系统结构或规则变更；云端接入的隐私条款必须根据官方资料和当前账户设置核验。
- **28 变更记录：** 只登记会影响系统结构、规则、权限、模板或模型接入的变更；普通笔记润色不登记。
- **29—32 决策习惯/记忆/日记/纠错档案：** R 只保留当前可执行规则；C 保存已发生的助手错误；E/I/B/F 按类型记录且同一事件只保留一份主记录。日记可选，不强制。
- **33 检索验收：** 只在规则变更、检索失败或抽样验收后使用；不保存完整私人对话或全量检索结果。

## 五、最小充分产出规则

- 只保留本次确实需要的字段和章节；可选章节不适用时整段删除。
- 没有依据的字段不猜填。若尚待核实且影响理解，写“待核实”并注明原因；否则删去空字段。
- 不保留模板说明、示例文本、占位编号、空表格或“待填写”占位噪音。
- 一条事实只在一个正式位置保存；其他位置用链接或编号引用。
- 不为了统一版式把叙述改成大表格，也不为了看起来完整增加字段。
- 正式文件生成后必须能独立阅读，不要求读者回模板查规则。
- 保留用户原话、事实来源和必要历史；事实、推测、建议和待验证内容分开。

## 六、版式选择

| 信息形态 | 优先形式 | 典型用途 |
|---|---|---|
| 同类字段需要横向比较 | 3—5 列短表格 | 决策方案、里程碑、风险、回顾目标 |
| 执行顺序严格 | 编号步骤 | SOP、安装流程、验收流程 |
| 独立原则或事实 | 短列表 | 系统规则、画像事实、知识要点 |
| 解释原因、限制和判断 | 短段落 + 小标题 | 知识、项目背景、决策依据 |
| 个人体验、感受、反思 | 自由叙述 | 日记、文献体验、回顾 |
| 需要状态跟踪 | 复选框或短索引 | 本周清单、验收清单 |
| 长期事件与修正历史 | 独立记录卡 + 索引 | 记忆、纠错、决策复盘 |

表格只放短值，不放长段说明、长摘录和完整操作步骤。具体排版边界见 `模板/23 模板排版决策规范.md`，只在重构结构时查阅。

## 七、统一元数据与排版

结构化正式笔记使用标准 YAML Frontmatter；无生命周期管理必要的文件不强制填写所有字段。

```yaml
---
类型: 知识
创建: {{date:YYYY-MM-DD}}
更新: {{date:YYYY-MM-DD}}
状态: 草稿
标签: []
---
```

- `类型`、`状态` 取值以 `系统维护/命名与属性规范.md` 为准。
- 日期使用裸日期 `YYYY-MM-DD`；月份 `YYYY-MM`；年度 `YYYY`。
- 属性名和值使用中文；平台强制的技术名称除外。
- 一篇笔记只使用一个一级标题，通常与文件名对应。
- `##` 为主要板块；`###` 用于子主题或重复记录。
- 普通笔记内部链接只保留真正有用的关联；入口和索引页不受链接数量限制。
- 标准 Markdown 为核心格式，不依赖特定插件保存唯一数据。

## 八、正式文件与运行时

- 正式文件包含实际需要保留的内容、边界和必要操作说明。
- 项目运行时查阅正式项目文件、已批准规则、当前任务来源及相关记录。
- 决策跟进回到该项原始决策；助手纠错先查有效 R，追溯才读 C；个人经验按主题查 E/I/B/F。
- 不要求每个项目读取全部决策和记忆历史，更不要求读取模板库。
- 模板里出现的字段、检查项或示例不自动成为运行期任务、提醒或巡检。

## 九、模板升级

- 模板版本升级只影响后续新建文件的参照标准。
- 已有正式文件保持原样，除非用户明确指定升级。
- 升级前先备份和比较差异，保留内容、来源、编号、确认记录与历史。
- 不自动搬迁、合并或重编号已有 C/R/E/I/B/F/D 记录。
- 升级项目模板不自动为已有项目创建项目定位、项目记忆或项目技能；缺少哪项先盘点，再由用户决定是否补齐。
- 修改模板后运行规则校验，并写入 `系统维护/变更记录.md`。

## 十、运行规则不是模板

`系统/助手回复规范.md`、`系统/用户信息采集计划.md`、`系统/记忆规则.md` 和 `系统维护/检索验收规范.md` 都是实际运行规则，不是供每次回答套用的模板。它们只在对应触发场景中作为正式规则读取；不应复制成每次任务的表单或话术。

## 十一、日常信息引导不是模板

渐进式采集与每日回顾由正式文件 `系统/用户信息采集计划.md` 触发。不要为每个问题创建一份模板或表单；只有形成正式画像/长期记忆更新时，才使用 21/22 号提案模板。

## 十二、七分制

七分制唯一正本是 `系统维护/命名与属性规范.md` 第六节。只用于个人体验或对象评价，不代表事实准确度、风险等级或科学证据等级。
