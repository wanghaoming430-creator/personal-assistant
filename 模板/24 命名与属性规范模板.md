# 命名与属性规范

## 目的

确保文件可读、可搜索、可迁移，并减少同一概念出现多个名称的情况。

## 语言与命名

- 日常文件夹、笔记文件名、属性、标签全部使用中文。
- 平台强制要求的技术文件名和目录名保留原文，例如 `系统/运行入口.md`、`SKILL.md`。
- 文献参考使用对象的常用中文名称；原文名写入“原名”属性。
- 文件名简短、唯一、可辨认，不堆叠多个分类前缀。
- 一次重要决策只建立一份决策记录；复盘和修正追加到原文件，不为每次修正另建同主题文件。

## 日期规范

| 使用场景 | 格式 | 示例 |
|---|---|---|
| 日期属性 | `YYYY-MM-DD`，不加引号 | `2026-11-14` |
| 即时想法文件名 | `YYYY-MM-DD HHmm` | `2026-11-14 1919` |
| 月度记录 | `YYYY-MM` | `2026-11` |
| 年度记录 | `YYYY` | `2026` |

裸日期是标准 YAML 的日期类型，Obsidian 属性面板按日期显示，Dataview 按时间排序；加引号会变成字符串，排序按字典序。

## 编号规范

- 决策记录编号：`D-YYYYMMDD-序号`，例如 `D-20261114-01`；同一天从 01 递增。
- 助手纠错事件沿用 `C-01` 起；规则沿用 `R-01` 起；全库唯一，不重排、不复用。
- 经验偏差沿用 `B-01` 起；分歧沿用 `F-01` 起；历史编号不因模板升级而改变。
- 历史文件已有编号时，优先沿用原编号，不为统一格式批量重编号。

## 通用属性字典

| 属性 | 含义 | 适用场景 |
|---|---|---|
| 类型 | 笔记类型 | 所有结构化笔记 |
| 创建 | 创建日期 | 需要追踪创建时间的笔记 |
| 更新 | 最近更新时间 | 会持续维护的笔记 |
| 状态 | 当前处理状态 | 项目、剪报、SOP、回顾等 |
| 标签 | 主题分类 | 需要跨目录检索时 |
| 来源 | 信息来源 | 外部资料和知识笔记 |
| 评分 | 个人七分制评分 | 体验、作品、工具、地点等 |
| 原名 | 外文或原始名称 | 有通行中文名的外文对象 |
| 决策编号 | 决策记录的唯一编号 | 人生决策 |
| 决策期限 | 最晚做出决定的日期 | 人生决策 |
| 复盘日期 | 计划复盘的日期 | 人生决策 |
| 项目状态 | 项目生命周期四状态 | 项目首页/项目主文件 |
| 规则范围 | 规则适用范围 | 规则、项目定位、项目记忆、项目技能 |
| 项目关联 | 所属项目名称 | 项目记忆、项目技能、项目相关记录 |

只为确有检索或管理价值的内容增加属性，不要求每篇笔记使用全部字段。

项目状态与通用状态分开：`项目状态` 只使用进行中、等待外部、已结项、归档；`状态` 仍按下方十六值词表，两者不能互相替代。

## 状态词表

十六个值，按「还能不能用」分三组。正本见 `系统维护/命名与属性规范.md` 2.2，这里是同一份。

- 还不能用：草稿、待处理、待回顾、待阅读、待观看、待确认、待验证、规划中、分析中
- 能用：进行中、使用中、已整理、已确认、已验证、生效
- 不用了：归档

一个文件只有一个状态，不写复合值。上表没有的值先改词表再加，不许就地发明。

## 标签规则

- 使用中文短语。
- 同一概念只保留一个标准写法。
- 不以标签数量作为完整度目标。
- 中文不强制套用英语复数规则；以固定词表保证一致性。

## 内部链接

- 普通笔记不超过 5 个有意义的链接。
- 入口、索引和导航页不受此上限限制。
- 使用标准 Markdown 相对链接。
- 决策修正记录链接回原决策编号；经验记忆只引用原决策，不复制全文。

## 新增字段审批

新增通用属性前，先记录字段名称、含义、适用范围和示例；确认不会与现有字段重复后再纳入字典。
