# 记忆与知识检索验收规范

> 验证模型是否在正确时机找到正确资料，并且没有多读不必要的内容。它不是全库巡检，也不要求记录每一次普通查询。

## 一、验收目标

检索质量同时看“找对”和“少读”。仅仅召回很多文件不代表检索成功。

1. **触发准确：** 该查时查，不该查时不查。
2. **来源准确：** 事实能回到正式文件或原始证据。
3. **时效正确：** 不把待复核、已失效或被替代的信息当作当前事实。
4. **范围克制：** 只打开与当前任务相关的少量文件和条目。
5. **写回正确：** 新信息进入唯一归属，不复制、不越权、不误升为长期记忆。

## 二、何时验收

- 新增或修改运行入口、记忆规则、用户信息采集规则、决策索引、规则适用范围、项目状态或检索方式后。
- 用户指出模型漏读、误读、读取过多、使用过期信息或错误引用。
- 每月抽样一次，选取少量真实任务；没有问题时不必为验收制造材料。
- 用户明确要求检查知识库检索能力时。

不在每次回答后运行完整测试，也不为普通问答生成检索日志。

## 三、标准测试场景

| 编号 | 输入场景 | 预期读取 | 不应读取 |
|---|---|---|---|
| T1 | 普通知识问答 | 当前问题所需资料 | 完整画像、长期记忆、决策历史 |
| T2 | 个性化建议 | 用户上下文摘要；不足时才查画像/长期记忆相关条目 | 全量个人档案 |
| T3 | 指定项目推进 | 该项目首页、项目定位、项目记忆、必要技能、必要任务清单 | 其他项目和全量记忆 |
| T4 | 与既有助手错误相似 | 先查匹配 R；必要时查关联 C；高优先级 C 优先提醒 | 全部 C 事件 |
| T5 | 重要决策或决策复盘 | 决策索引及同主题记录 | 无关决策档案 |
| T6 | 信息发生变化或与旧记忆冲突 | 新信息来源、旧条目及其有效性字段 | 无关用户信息 |
| T7 | 每日引导/回顾 | 采集计划及当天必要记录 | 全量日记和所有画像字段 |
| T8 | 新建或升级文件 | 目标文件的一份模板及相关正式规则 | 整个模板目录 |
| T9 | 跨项目问题 | 识别真正可共享的方法，核对适用边界 | 把项目专属规则当全局、批量加载其他项目记忆 |
| T10 | 项目状态识别 | 按四种项目状态正确判定；等待外部不当作结项，归档默认排除 | 把所有未结项都当进行中，或把等待外部当失败 |
| T11 | 规则适用范围判断 | 先判断全局/项目类型/项目专属/待验证 | 把单个项目问题直接升级为全局规则 |
| T12 | 本地短任务 | 999 tokens 内完成单一任务，只引用一份短资料 | 加载多个文件、完整全局提示词或长历史 |
| T13 | 断网应急 | 本地聊天和显式文件引用可用 | 依赖云端 Embedding |
| T14 | 周度睡眠学习 | 围绕真实问题和相关文件增量检查 | 无差别全库扫描、强行制造规则 |
| T15 | 提示词修改 | 有真实案例、回归测试和用户确认 | 只凭模型主观判断升级 |

知识类检索包括 `内容/知识/` 与 `沉淀/概念/`；沉淀分析页按知识页同样验收，不因目录不同降低来源、计数和状态要求。

## 四、单次验收记录维度

每项按通过/失败记录，不用虚假的精确分数：

- 触发是否正确：是 / 否
- 是否命中正确来源：是 / 否
- 是否使用了最新有效信息：是 / 否 / 不适用
- 是否读取了不必要文件：是 / 否
- 是否正确遵守写入审批和唯一归属：是 / 否 / 不适用

只在失败或有代表性的抽样时记录详细说明。不要保存整段私人对话作为测试样本；用任务类型、文件路径和必要的脱敏摘要即可。

## 五、失败分类与修复

| 失败类型 | 常见原因 | 优先修复 |
|---|---|---|
| 漏触发 | 触发条件太窄、入口未引用 | 补触发信号和路由 |
| 误触发 | 规则太宽、普通任务也查记忆 | 收窄条件，加入明确排除项 |
| 漏召回 | 索引字段缺失、主题命名不一致 | 修复索引和命名，不先加大上下文 |
| 错误召回 | 同义重复、分类混淆 | 去重并明确唯一归属 |
| 过期召回 | 缺少复核日期或失效状态 | 补有效性字段，过期先核验 |
| 过度读取 | 入口允许全量展开、默认取太多结果 | 限定先读 1—3 个命中项，再按需扩展 |
| 错误写回 | 事实/推断混淆或审批边界不清 | 修复记忆准入规则和提案流程 |
| 跨项目误召回 | 项目规则未标范围、项目记忆互相复制 | 补 `项目关联`/`规则范围`，回到项目层 |
| 项目状态误判 | 把等待外部当结项、把归档当进行中 | 按 `项目状态` 四值修正，补恢复条件 |
| 规则泛化错误 | 单项目问题直接升全局、缺少反例 | 回到 [[系统维护/规则适用范围与升级规范]]，降级或标待验证 |
| 本地超限 | 一次加载多个文件或长提示词 | 拆成单文件单段微任务，压到约 800 tokens 内 |

修复时优先修改源头规则、正式索引或属性；不以增加更多摘要、更多模板或更多常驻文件解决检索问题。

## 六、通过标准

一个场景通过必须同时满足：

- 触发判断正确；
- 关键结论能定位到正确来源；
- 没有把已失效/待确认资料当成确定事实；
- 没有读取明显无关的完整文件或目录；
- 没有越过写入权限。

同一类失败在后续抽样中再次出现，说明修复未完成；应回到规则或索引层查原因，而不是简单增加提醒文字。

## 七、验收留痕

- 代表性失败和结构变更后的验收，使用 `模板/33 检索验收记录模板.md` 形成记录。
- 通过的普通抽样不必逐项建档，可在月度回顾中写一句结果。
- 结构规则变更写入 `系统维护/变更记录.md`；单次检索故障不必升级为系统变更。
- 不记录原始敏感对话，不把检索测试库变成第二份用户记忆。
