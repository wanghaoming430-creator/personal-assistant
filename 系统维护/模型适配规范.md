# 模型适配规范

> 本文件记录模型无关的能力要求、云端与本地运行边界和降级方式。它不绑定任何模型供应商，也不要求某个插件作为入口。

## 一、模型无关原则

1. Markdown / YAML 是正式数据正本，模型和插件都不是记忆正本。
2. 换模型不得改变文件结构、编号、属性、唯一归属和审批规则。
3. 云端与本地模型读取同一套知识库文件，不设置资料分级授权；检索按任务相关性和上下文容量控制。
4. 写入权限不因模型来源自动变化：普通知识整理按既有权限执行；画像、长期记忆、系统规则、助手人格、回复规范仍需用户确认；删除、覆盖、批量重命名、对外发送每次单独确认。
5. 不把知识库内容自动写入模型服务商自带的长期记忆。
6. 不为不同供应商分别设计一套个人助手规则。平台差异只在入口和接入层处理。

## 二、能力要求

任何承担主力工作的模型或 Agent 平台，至少应具备：

| 能力 | 要求 | 不满足时的处理 |
|---|---|---|
| 读取文件 | 能读取用户指定的 Markdown/YAML 文件或片段 | 无法读取时明确报告能力限制，不凭记忆作答 |
| 按需检索 | 能按文件名、主题或关键词定位资料 | 退回用户显式指定文件 |
| 区分事实与推断 | 能区分已确认事实、候选、建议和待验证内容 | 输出中逐项标注，不合并成结论 |
| 遵循写入边界 | 受保护文件先提案后写入 | 只输出候选文本，由用户手动应用 |
| 展示修改范围 | 能说明改了哪些文件、哪些段落 | 写入前列出差异 |
| 长上下文控制 | 不全量加载 Vault | 按 [[运行入口]] 的 L0–L5 分层读取 |

## 三、云端主力运行

- 用户在所选云端 Agent 平台中直接操作知识库。
- 云端平台如何接入文件系统、同步、凭据和工具权限，由用户在该平台单独配置；本库不假定已完成。
- 云端 Agent 只需遵守知识库操作协议，不要求接入 Smart Composer，也不要求使用某个产品或 API。
- 平台无法实际读写 Vault 时，应明确报告限制，不得声称已操作文件。

操作协议：

1. 以当前 Vault 中的正式 Markdown/YAML 为唯一事实来源。
2. 处理项目任务时先识别项目，再读取项目定位、项目记忆和当前任务需要的技能。
3. 不把项目专属规则直接升级为全局规则。
4. 写入前检查是否已有同一主记录，避免重复建档。
5. 受保护文件先提交差异、来源和理由，确认后修改。
6. 普通知识整理可按既有权限在指定范围内进行，保留来源和必要历史。
7. 删除、覆盖、批量重命名和库外操作每次单独确认。
8. 不把知识库内容自动写入模型服务商自带的长期记忆。

## 四、本地应急运行

当前本地配置见 [[系统维护/Smart Composer本地配置说明]]。

- 只处理短小、单步、低风险任务：单条分类、属性提取、短摘要、标题/标签候选、单段格式整理、单条记忆事件的初步分类候选。
- 本地模型产生的规则、记忆或技能更新只作为候选，不能自行批准或写入正式规则。
- 本地实际上下文按 999 tokens 硬上限设计，不拿模型理论窗口替代。
- 完整睡眠学习、跨项目规则泛化、C/R 冲突裁定、全库检索分析不在本地执行。

## 五、降级与失败处理

| 情况 | 处理 |
|---|---|
| 云端不可用 | 切到本地模式，只做微任务；复杂任务排队等云端恢复 |
| 本地上下文不足 | 缩小到单文件单段，或拆成多个独立微任务 |
| 本地模型无法稳定工具调用 | 退回“生成候选文本—用户手动应用” |
| 模型无法读取文件 | 明确报告能力限制，请用户粘贴必要片段 |
| 模型输出与库内规则冲突 | 以库内正式规则为准，记录冲突，不静默覆盖 |

## 六、适配验收

- 换模型后，原有文件结构和编号不变。
- 新模型能按指定文件回答，不要求全库导入。
- 能区分建议、候选、已确认事实和最终决定。
- 能在用户确认后修改指定文件，并展示修改差异。
- 不会把模型平台记忆当作知识库正式记录。
- 不会自动读取模板、工作台或全量历史资料。
- 断开模型服务后，Vault 内文件仍可独立阅读和编辑。
