# 每周睡眠学习规范

> 睡眠学习不是模型训练，也不是自动重写整套提示词。它是围绕本周真实运行问题，对规则、项目记忆和项目技能做增量维护的周度流程。

## 一、触发与执行位置

- 由用户在云端 Agent 平台手动启动：输入 `/每周睡眠学习`，或明确提出“执行本周睡眠学习”。
- 本地 Smart Composer + Qwen3-8B Q4 的 999-token 模式不执行完整睡眠学习，只可在明确授权下做单条候选整理。
- 没有外部调度能力时，不得声称已设置后台自动学习或定时任务。

## 二、输入优先级

1. 本周实际发生的错误、纠正、执行偏差和用户指出的问题。
2. 与上述问题直接相关的 C/R 记录、项目定位、项目记忆、项目技能和正式项目文件。
3. 本周新增或实质修改的项目文件、过程记录、成果和复盘。
4. 已结项项目的结项材料，仅用于提炼经验，不重新进入执行队列。
5. 与本周问题有关的必要历史证据。

## 三、默认不做

- 不建立首次全库基线学习。
- 不无差别重扫全部历史文件。
- 不读取模板库作为学习材料。
- 不把归档项目纳入常规周度学习。
- 不因为文件数量多就强行生成规则或提示词。
- 不为了完成形式而制造“优化”。

## 四、项目状态与学习范围

| 项目状态 | 处理方式 |
|---|---|
| 进行中 | 检查本周新增/修改资料及实际问题，必要时更新项目记忆和技能候选 |
| 等待外部 | 检查外部反馈、条件变化和等待状态；无变化则不强行生成优化 |
| 已结项 | 仅检查结项复盘和仍有价值的经验，评估是否提炼为可复用方法 |
| 归档 | 默认排除；只有本周问题明确引用该项目时才读取相关历史 |

## 五、学习步骤

1. 收集本周实际问题与用户反馈，标明来源和所属项目。
2. 按问题定位所属项目和相关正式文件。
3. 检查已有 C/R、项目记忆和项目技能，确认是否已有处理规则。
4. 找出根因，区分：模型理解问题、规则缺失、技能步骤缺失、记忆缺失、检索错误、执行能力限制。
5. 按 [[系统维护/规则适用范围与升级规范]] 判断优化范围：全局通用、项目类型通用、项目专属或证据不足。
6. 生成最小必要的修改候选，不为小问题改动无关文件。
7. 用真实案例构造测试：原问题、相似任务、边界例外、跨项目误用、反例。
8. 对比修改前后结果，检查是否解决原问题、是否引入新问题、是否增加不必要提示词。
9. 生成变更提案，列出涉及文件、前后差异、证据、影响范围、测试结果和回滚方式。
10. 涉及受保护规则的变更经用户确认后写入；确认后更新版本和 [[系统维护/变更记录]]。

## 六、输出

每周只输出有价值的结果：

- 本周发现的真实问题（带来源）
- 根因判断及不确定项
- 规则适用范围判断
- 项目记忆、项目技能、全局 R 的修改候选
- 提示词修改候选及修改理由
- 回归测试结果
- 待用户确认事项

没有值得修改的项目时，明确记录“本周无必要规则/提示词变更”。

## 七、验收

- 每个修改候选都能指回本周的真实问题。
- 没有把项目专属问题直接升级成全局规则。
- 至少检查一个原问题、一个相似任务和一个反例。
- 修改前后差异、测试结果和回滚方式齐全。
- 模板、工作台、归档项目没有被无差别加载。
- 受保护文件改动已获用户确认。

## 八、留痕与回滚

- 修改前保留原文件或 Git 备份。
- 变更编号建议使用 `V1.5-序号-主题`，写入 [[系统维护/变更记录]]。
- 新规则导致旧场景退化时，回滚到上一个已验证版本，再分析原因。
- 不因升级规则而自动批量升级已有项目文件。
