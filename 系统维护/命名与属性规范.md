# 命名与属性规范

## 一、文件命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 普通知识 | 简短清楚的中文主题名 | `模型选型对比.md` |
| 沉淀分析页 | 简短清楚的中文主题名，放 `沉淀/概念/` | `参考来源乙的构图与调色特征.md` |
| 文献参考 | 对象的常用中文名，原名写正文 | `《人类简史》.md` |
| 即时想法 | `YYYY-MM-DD HHmm` 加可选描述 | `2026-11-14 1745 项目方向.md` |
| 日记 | `YYYY-MM-DD` | `2026-11-15.md` |
| 阶段回顾 | `YYYY-MM-DD 阶段回顾` | `2026-11-20 阶段回顾.md` |
| 月度回顾 | 该月首日 | `2026-11-01 月度回顾.md` |
| 年度回顾 | 该年首日 | `2026-01-01 年度回顾.md` |
| 决策记录 | `YYYY-MM-DD 主题` | `2026-11-20 是否接这单.md` |
| 项目首页 | `项目首页` | `内容/项目/创作项目/项目首页.md` |
| 项目定位 | `项目定位` | `内容/项目/创作项目/项目定位.md` |
| 项目记忆 | `项目记忆` | `内容/项目/创作项目/项目记忆.md` |
| 项目技能 | 按实际场景命名 | `商品标题撰写.md`、`项目资料来源核验.md` |
| 剪报 | 保留原题名 | `萧萧落木不胜秋.md` |

项目技能禁止用「技能一」「技能二」「通用技能」等占位名称。技能名称应能让用户一眼看出具体工作场景和结果。

文件名避免特殊符号，避免长标题。`HHmm` 是时间戳专用例外，其他日期一律 `YYYY-MM-DD`。

`沉淀/概念/` 用于从多篇剪报或资料归纳出的分析页，不另立新类型，仍用 `类型: 知识`，并纳入知识索引与规则校验。单篇原始资料留在 `外部收件箱/`，不直接进沉淀层。

剪报是唯一例外：题名由原文决定，原作者用 emoji、空格、拉丁字母时按原样保留，改名会切断与原文的对应关系。其余类型不适用此例外。

## 二、属性字段

只用这些，不够再加，不为了查询方便提前堆字段。

| 字段 | 用途 | 取值 |
|---|---|---|
| `类型` | 笔记种类 | 见 2.1 |
| `创建` | 建立日期 | `YYYY-MM-DD` |
| `更新` | 最后实质修改 | `YYYY-MM-DD` |
| `状态` | 生命周期 | 见 2.2 |
| `标签` | 主题词表 | 见第三节 |
| `来源` | 从哪来 | 自主总结、用户原话、网页链接、书名 |
| `评分` | 七分制 | 1 至 7，仅用于评价类笔记 |
| `地区` | 适用地区 | 仅用于有地域差异的内容 |
| `确认` | 是否经用户确认 | 已确认、未确认、待确认 |
| `项目状态` | 项目生命周期，只用于项目 | 进行中、等待外部、已结项、归档 |
| `规则范围` | 规则适用范围，只用于规则类内容 | 全局通用、项目类型通用、项目专属、待验证 |
| `项目关联` | 该条内容所属项目 | 项目名称，可空 |

### 2.1 类型词表

分为内容类、记录类和系统类三组。这个表是校验脚本的依据，新增值先改这里，不允许就地发明。

**内容类（会被 Dataview 索引页查询）**

| 值 | 用在哪 | 被谁查 |
|---|---|---|
| 知识 | `内容/知识/`；`沉淀/概念/`（多篇归纳的分析页，仍属知识） | `知识索引` |
| 项目 | `内容/项目/` | `项目索引` |
| SOP | `内容/流程/` | `流程索引` |
| 剪报 | `外部收件箱/剪报/` | `剪报索引` |
| 书籍 / 电影 / 人物 / 地点 / 播客 | `外部收件箱/文献参考/` | `文献参考索引` |
| 日记 | `日志/即时想法/` | `即时想法索引` 的「日记」一节 |
| 即时想法 | `日志/即时想法/` | `即时想法索引` |
| 阶段回顾 / 月度回顾 / 年度回顾 | `日志/` 对应子目录 | 三张回顾索引 |
| 人生决策 | `内容/决策/` | `决策索引` |
| 索引 | 各目录的 `*索引.md` | 不查，本身是索引 |

**记录类**

个人画像、长期记忆、助手工作规则、助手纠错档案、个人经验记忆、用户上下文摘要、记忆规则、用户信息采集计划、检索验收记录、本周清单、个人画像更新提案、长期记忆更新提案、审计报告、过程留痕（`日志/` 下的提案、台账、差异清单）、项目定位、项目记忆、项目技能、提示词。

**系统类**

系统入口、运行规则、助手人格、助手回复规范、系统规则、权限与隐私规则、命名与属性规范、数据流转规则、云端模型接入说明、检索验收规范、系统变更记录、方法库、规则适用范围与升级规范、睡眠学习规范、模型适配规范、Smart Composer本地配置说明。

系统类文件允许用自己的文件名当类型。这是现状，不是理想态：好处是不用额外字段就能认出来，坏处是按类型归组时它们各占一格。若要统一成 `类型: 系统` 加标签细分，属结构改动，走单独确认，不在这里顺手改。

### 2.2 状态词表

16 个值。每个值说明「下一步要做什么」，状态才有意义。

**还不能用**

| 值 | 含义 | 只用于 |
|---|---|---|
| 草稿 | 没写完 | 知识、SOP、回顾 |
| 待处理 | 收件箱里，还没消化 | 剪报 |
| 待回顾 | 记下了，还没回看 | 即时想法 |
| 待阅读 | 还没读 | 书籍 |
| 待观看 | 还没看 | 电影 |
| 待确认 | 等用户答复 | 各类更新提案 |
| 待验证 | 有结论，证据没到位 | 知识、云端模型接入说明 |
| 规划中 | 项目还没启动 | 项目 |
| 分析中 | 决策还在论证 | 人生决策 |

**能用**

| 值 | 含义 | 只用于 |
|---|---|---|
| 进行中 | 本周在做 | 本周清单 |
| 使用中 | 日常在用，内容有效 | 索引、画像、长期记忆、项目、记忆类 |
| 已整理 | 消化完，可引用 | 知识 |
| 已确认 | 用户确认过 | 长期记忆、画像 |
| 已验证 | 实测通过 | 云端模型接入说明、知识 |
| 生效 | 规则当前有效 | 系统规则类四份、助手人格 |

**不用了**

| 值 | 含义 | 只用于 |
|---|---|---|
| 归档 | 不再维护，只留历史 | 任何类型 |

三条硬要求：

1. 一个文件只有一个状态，不写「已整理／待验证」这种复合值。
2. 上表没列的值，先改本节再加，不许就地发明。
3. 不跟踪生命周期的文件（模板说明、变更记录）可以省略 `状态` 字段，不要写「无」。

### 2.3 项目状态与规则范围

`项目状态` 与笔记通用属性 `状态` 分开管理，不能相互替代。`项目状态` 只描述项目生命周期，只用于项目首页或项目主文件。

| 项目状态 | 定义 | 运行方式 |
|---|---|---|
| 进行中 | 项目正在推进，有明确目标和下一步 | 参与正常项目工作和周度学习 |
| 等待外部 | 等待外部人员、资料、审批、供应商或条件 | 保留等待事项、责任对象、恢复条件和跟进日期；不误判为结项 |
| 已结项 | 项目目标完成，交付成果通过验收 | 保留结项总结和成果；不进入普通执行队列 |
| 归档 | 项目退出当前活动范围，作为历史资料保留 | 默认不参与日常运行和周度学习，需要时仍可检索 |

状态流转：

- 进行中 ↔ 等待外部：条件变化时恢复或进入等待。
- 进行中 → 已结项：目标完成且验收通过。
- 等待外部 → 已结项：外部事项解决，且达到结项验收条件。
- 已结项 → 归档：结项材料和经验已整理。
- 归档 → 进行中：用户明确重新启用，保留历史，不新建重复项目。
- 取消的项目不增加第五种状态；记录取消原因后归档。

`规则范围` 只用于规则、项目定位、项目记忆、项目技能等需要标明适用范围的正式文件：

| 规则范围 | 含义 |
|---|---|
| 全局通用 | 所有任务和项目适用 |
| 项目类型通用 | 只适用于一类具有明确共同特征的项目 |
| 项目专属 | 只在所属项目生效 |
| 待验证 | 证据不足，保留候选，不升级为正式规则 |

判据与提级条件见 [[系统维护/规则适用范围与升级规范]]。

### 2.4 日期格式

一律写裸日期 `YYYY-MM-DD`，不加引号。

裸日期是标准 YAML 的日期类型，Obsidian 属性面板会显示日期选择器，Dataview 排序按时间走；加了引号就变成字符串，排序按字典序。全库已统一为裸日期，模板同步。

空值写 `""`。日期字段没确定时不要填占位文字。

## 三、标签

统一中文词表，一个概念只用一个词。不出现「项目/Projects」这种中英混写，也不为同一意思造近义词。

现有标签：`系统`、`助手`、`画像`、`记忆`、`待办`、`知识`、`项目`、`流程`、`剪报`、`文献`、`回顾`、`决策`、`审计`、`学习`、`每日计划`、`用户信息`、`检索`、`回复`。

## 四、链接

- 普通笔记最多 5 个真正有用的内部链接。
- 入口、索引、导航页不受此限，它们的职责就是导航。
- 用标准 Markdown 链接，不把 `[[双链]]` 当唯一格式。
- 没有明确关系就不强行连。

## 五、编号与决策属性

- 决策记录编号 `D-YYYYMMDD-序号`，同一天从 01 递增。一次重要决策只有一个编号，复盘和修正追加在原记录里，不另开新号。
- 助手纠错事件从 `C-01` 起，工作规则从 `R-01` 起；经验从 `E-01` 起，觉察从 `I-01` 起，任务偏差从 `B-01` 起，分歧从 `F-01` 起。
- 编号全库唯一，不重排、不复用。被推翻的规则保留原编号和原文，不改写历史。
- 决策专用属性三个：`决策编号`、`决策期限`、`复盘日期`，只用于决策记录。
- 历史文件已有编号时沿用原编号，不为统一格式批量重编号。

## 六、七分制

本表是七分制的唯一正本。其他文件需要时引用本节，不复述。

| 分 | 标准 |
|---|---|
| 7 | 完美，必须体验，可能改变人生，值得专程前往 |
| 6 | 非常优秀，值得重复体验 |
| 5 | 不错，但不值得专门绕路 |
| 4 | 勉强可以接受，必要时能满足需求 |
| 3 | 不好，能避免就避免 |
| 2 | 非常糟糕，应主动避开 |
| 1 | 极其恶劣，可能以负面方式改变人生 |

用于个人体验、对象、产品、工具和方法的评价。不替代证据等级、风险等级或项目验收标准。

## 七、校验

规则写在文档里，靠人记得去读，实际执行率接近 0。本节的检查由脚本执行，不靠自觉。

```bash
cd <库根目录> && python3 系统维护/规则校验.py
```

脚本只读，不改文件。检查以下项目：类型词表、状态词表、项目状态词表、规则范围词表、知识页目录、日期格式、0 字节文件、同名文件、断链、索引页查询条件、入口数字与空目录。本库另保留一项 Smart Composer RAG 排除检查，防止模板、画像与长期记忆被自动索引。

输出分两级：

- `FAIL` 硬错，必须改。退出码 1。
- `WARN` 警告，看一眼再决定。退出码 2。

豁免写在脚本的 `WAIVERS` 与 `WAIVER_PATTERNS` 里，每一条都要写理由。想放过一项，就在脚本里写明为什么放过，不要靠沉默通过。

建议每周跑一次，改完规则或模板后也跑一次。哪天脚本说全部通过，这套格式才算真的成立。
