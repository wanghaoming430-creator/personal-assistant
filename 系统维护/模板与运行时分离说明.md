# 模板与运行时分离说明

模板只管「文件长什么样」，正式文件才管「事情怎么办」。这两件事分开，是为了让运行时不背一堆制作规范。

## 一、两类文件的职责

### 模板库

`模板/` 回答的是：新建或重构某种文件时，应该包含什么字段、什么结构、什么版式。

它不承担项目管理、任务执行、事实存储、决策追踪或记忆召回。模板里的内容不构成项目指令，也不自动产生待办、提醒或周期任务。

### 正式文件

由模板产出的正式文件才承担实际职责：

| 正式文件 | 职责 |
|---|---|
| `系统/运行入口.md`、`系统/系统规则.md`、`系统/助手人格.md` | 实际运行规则 |
| `个人/个人画像.md`、`个人/长期记忆.md` | 经确认的稳定信息 |
| `个人/本周清单.md` | 唯一任务源 |
| `内容/项目/*` | 项目首页、项目定位、项目记忆、项目技能、背景、边界、决策与成果 |
| `内容/流程/*` | 可执行的 SOP |
| `内容/知识/*`、`沉淀/概念/*` | 消化后的结论与多篇归纳分析页 |
| 单项决策记录 | 当时依据、最终决定、执行、复盘、追加修正 |
| `系统/决策习惯.md` | 助手纠错事件 C、已沉淀规则 R、分歧 F |
| `个人/记忆.md` | 萃取、觉察、偏差、分歧 |

## 二、什么时候读模板

只在这三种情况读对应模板：

1. 新建一份该类型文件。
2. 用户明确要求重构现有文件的结构或版式。
3. 用户明确要求把现有文件升级到新模板版本。

只读当前目标那一份，不必打开整个模板库。

## 三、什么时候不读模板

- 推进具体项目或处理项目内任务。
- 执行已建立的 SOP。
- 跟进某项决定、补证据、做复盘。
- 处理与既有经验或纠错规则有关的日常问题。
- 普通问答、资料查询、任务状态更新。

这些情形用已经产出的正式文件。模板目录不进 模型默认上下文、自动索引、RAG、向量库和周期扫描。

## 四、运行期按需读取

不读模板，不等于不读记忆或规则。正式文件按相关性查：

- 与某项决定有关：查该项决策记录和相关证据。
- 与助手犯过的同类错误有关：检索 `系统/决策习惯.md` 里匹配的 R 规则，必要时看对应 C 事件，不全量翻 C 流水。
- 与个人经历有关：检索 `个人/记忆.md` 里相关的萃取、觉察或偏差条目，不要求每个任务都读全部历史。
- 项目执行：以正式项目说明、`个人/本周清单.md` 和已确认的系统规则为依据。

## 五、模板升级不等于正式文件升级

- 改模板只改变以后产出文件的标准。
- 已有正式文件不会因为模板升版自动重写。
- 要升级某份旧文件，先指定目标文件，再比差异，保留已写内容和历史证据。
- 系统规则、个人画像、长期记忆等受审批保护的文件，仍按原授权流程走。
- 不因为模板里多了个字段或步骤，就自动把它加进现有项目或创建任务。

## 六、本库怎么落地

1. 模板留在 `模板/`，Obsidian 核心插件 Templates 指向它，方便手动插入。
2. 模型调用侧靠 [[运行入口]] 的上下文预算和 [[系统规则]] 的「模板与运行时分离」原则约束，项目运行时不读该目录。
3. 本库不要求接入 RAG 或向量库。若未来接入，索引范围必须显式排除 `模板/`、`系统/工作台.md` 和历史日志。
4. Obsidian 自己的全文搜索仍会搜到模板内容，这是客户端行为。搜到不等于要用，运行期判断以正式文件为准。
5. 模板升级或替换前先备份，改完写 [[系统维护/变更记录]]。
